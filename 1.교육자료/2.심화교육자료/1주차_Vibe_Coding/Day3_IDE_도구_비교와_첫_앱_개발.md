# 🚀 1주차 3일차: IDE 도구 비교분석과 첫 칸반(Kanban) 앱 자율 개발 실습

안녕하세요! 시니어 멘토입니다.

어제 우리는 LLM의 기억상실증을 보완하기 위한 컨텍스트 엔지니어링과 `agents.md` 설정법을 배웠습니다. 오늘은 이러한 이론을 실전에 대입하여, **2026년 현재 가장 널리 쓰이는 4대 AI 코딩 IDE 및 도구들을 비교**해 보고, 이를 활용해 **칸반(Kanban) 보드 애플리케이션**을 자율 개발하는 실습을 진행하겠습니다.

## ☕ 1분 비유: 4대 AI 코딩 도구는 랠리 레이싱의 보조 드라이버(Co-Driver)다
울퉁불퉁한 오프로드를 달리는 랠리 레이싱에서 운전자는 개발자이고, 옆자리의 네비게이터는 AI입니다.

```text
1. GitHub Copilot (심플 네비게이터)
   - "다음 우회전입니다"라고 운전자의 핸들 꺾는 타이밍에 맞춰 짧고 빠르게 지시합니다. (인라인 자동완성 최강자)

2. Cursor AI (적극적 보조 드라이버)
   - "앞에 웅덩이가 있으니 제가 잠시 핸들을 잡고 피해 갈게요"라며 운전석 컨트롤을 넘겨받아 차선을 바꿉니다. (Composer 멀티파일 자율 수정)

3. OpenAI Codex (마스터 엔지니어)
   - 흙길용 타이어 배치와 서스펜션 세팅을 한 장의 정밀 도면으로 완벽히 설계하여 한 번에 차를 튜닝해 줍니다. (단발성 대량 코드 생성 최강자)

4. Google Antigravity (최첨단 AI 레이더 위성)
   - 레이싱 경기장 전체 지도와 날씨 변화, 관람객 이동 흐름(200만 토큰 대규모 컨텍스트)을 실시간으로 스캔하여, 완벽한 전체 주행 경로 계획서(Plan)를 작성해 줍니다. (대규모 설계 및 추론 최강자)
```

## 🎯 Section 1: 4대 AI 코딩 도구 상세 비교분석

2026년 현재 상용 개발 및 바이브 코딩에 활용되는 핵심 도구들은 다음과 같은 독자적인 기술적 특성을 지니고 있습니다.

### 1. Cursor AI
- **핵심 기술**: VS Code를 포크(Fork)하여 만든 AI 전용 IDE.
- **주요 기능**: `Ctrl + K` (인라인 코드 수정), `Ctrl + L` (채팅 에이전트), `Ctrl + I` (Composer - 멀티 파일 동시 편집 에이전트).
- **특징**: 프로젝트 소스코드 전체를 로컬에 벡터 데이터베이스로 인덱싱하여 의미론적 코드 검색(Semantic Search)이 매우 뛰어납니다.

### 2. GitHub Copilot
- **핵심 기술**: 기존 IDE(VS Code, IntelliJ 등)의 플러그인 형태로 동작.
- **주요 기능**: 인라인 자동완성(Tab Completion) 및 Copilot Chat 패널.
- **특징**: 주석을 쓰면 코드를 채워주는 단순 자동완성 속도가 압도적으로 빨라 일반 타이핑 보조에 적합합니다.

### 3. OpenAI Codex (VS Code Extension)
- **핵심 기술**: GPT-5.2 Codex 모델 기반의 고성능 자율 코드 생성 엔진.
- **주요 기능**: Zero-shot 및 Few-shot 기반의 파일 단위 고속 생성.
- **특징**: 여러 단계를 거치지 않고 프롬프트 한 번에 복잡하고 정밀한 비즈니스 로직(예: 정렬 알고리즘, 복잡한 데이터 바인딩)을 버그 없이 한 번에(Zero-Shot) 짜는 능력이 매우 강력합니다.

### 4. Google Antigravity IDE
- **핵심 기술**: Google Gemini 3 Pro 추론 모델과 밀착 결합된 차세대 개발 환경.
- **주요 기능**: 200만 토큰 컨텍스트 지원, Plan-Execute-Review 오토 파일럿 모드.
- **특징**: 수천 개의 파일로 이루어진 복잡한 프로젝트 전체를 메모리에 올린 채로 설계 오류나 리팩토링 범위를 진단하는 능력이 타의 추종을 불허합니다.

## 🎯 Section 2: `agents.md`와 Cursor 환경설정 전략

Cursor AI 등 에이전트 도구를 사용할 때 성능을 극대화하려면 환경설정을 올바르게 튜닝해야 합니다.

1. **`.cursorrules` / `agents.md` 활성화**:
   - 프로젝트 최상위 폴더에 `agents.md`를 생성해 프로젝트의 아키텍처 규칙을 적어둡니다.
   - Cursor는 인덱싱 과정에서 이 규칙 파일을 자동으로 컨텍스트에 포함하여, 생성되는 코드가 규칙을 이탈하지 않도록 가이드합니다.
2. **YOLO 모드 활성화 (Cursor Composer Settings)**:
   - 개발 속도를 극대화하기 위해 에이전트가 터미널 명령어 실행(`npm run dev` 등)이나 파일 덮어쓰기 권한을 가질 때, 매번 팝업 승인을 받지 않고 자율적으로 연속 작업을 하도록 설정을 조율합니다.

## 🎯 Section 3: [실습] 4대 도구로 칸반(Kanban) 보드 제작 프로젝트

동일한 목표를 바탕으로 각 도구가 어떻게 코드를 구축하는지 살펴봅시다.

* **요구사항**: 
  - Todo, Doing, Done 3개의 열(Column) 제공.
  - 카드를 마우스로 드래그 앤 드롭(Drag & Drop)하여 다른 열로 이동 가능.
  - 새 카드 추가 모달(Modal) 창 및 카드 삭제 기능 포함.
  - 로컬 스토리지(LocalStorage)를 활용하여 새로고침해도 데이터 유지.

```mermaid
graph LR
    subgraph UI
        Todo["할 일 (Todo)"] -->|Drag & Drop| Doing["진행 중 (Doing)"]
        Doing -->|Drag & Drop| Done["완료 (Done)"]
    end
    subgraph Storage
        Todo -.->|Save/Load| LS["LocalStorage (로컬저장소)"]
        Doing -.->|Save/Load| LS
        Done -.->|Save/Load| LS
    end
end
```

### 1. Cursor AI (YOLO Mode)의 접근 방식
- **동작**: `Ctrl + I`를 누르고 "칸반 앱을 만들어줘"라고 지시하면, HTML, CSS, JavaScript 파일을 분리하여 생성하고, 로컬 웹서버 실행 명령어까지 터미널에 알아서 입력합니다.
- **장점**: 대화하듯 빠르게 기능을 쪼개어 붙이기 좋습니다.
- **단점**: 간혹 에이전트가 이전에 짜둔 자바스크립트 변수명을 망각하고 중복 코드를 생성해 버그를 유발하기도 하므로, 개발자가 코드 변경점(Diff)을 꼼꼼히 리뷰해야 합니다.

### 2. GitHub Copilot의 접근 방식
- **동작**: `index.html`을 만들고 주석으로 `// HTML5 drag and drop kanban board implementation`이라고 적은 뒤 Tab 키를 연타하여 작성합니다.
- **장점**: 개발자가 타이핑하는 흐름을 방해하지 않습니다.
- **단점**: 멀티 파일 수정(CSS와 JS의 동시 변수 연동 등) 시에는 채팅창을 열어 일일이 수동 가이드를 주어야 하므로 다소 번거롭습니다.

### 3. OpenAI Codex (GPT-5.2)의 접근 방식
- **동작**: 단 한 줄의 프롬프트만으로 복잡한 드래그 앤 드롭의 에지 케이스(예: 카드가 열 바깥으로 떨어졌을 때의 예외 처리)까지 완벽히 구현한 400줄짜리 스크립트를 실수 없이 단번에 출력해 냅니다.
- **장점**: 단발성 논리 정확도가 극도로 높습니다.

### 4. Google Antigravity (Gemini 3 Pro)의 접근 방식
- **동작**: 코드를 짜기 전에 먼저 `1. UI 레이아웃 설계`, `2. 드래그앤드롭 이벤트 바인딩`, `3. 로컬스토리지 스키마 정의`와 같이 상세 구현 계획을 요약한 뒤, 단계별로 승인을 받으며 코드를 빌드합니다.
- **장점**: 아키텍처가 매우 깔끔하고 정돈된 형태로 작성됩니다.

## 🏗️ 아키텍트의 의사결정 노트 (ADR - Architectural Decision Record)

### 결정사항: 2026년 실무 도구 선택 가이드 - 최종 벤치마크 평결 (Final Verdict)
- **배경**: 여러 도구가 난립하는 상황에서 개발 팀의 생산성을 극대화하기 위한 단일 도구 기준을 수립해야 합니다.
- **최종 비교 분석**:

| 비교 항목 | Cursor AI | GitHub Copilot | OpenAI Codex | Google Antigravity |
| :--- | :--- | :--- | :--- | :--- |
| **코딩 지능 (IQ)** | ★★★★☆ (4.5) | ★★★☆☆ (3.5) | ★★★★★ (5.0) | ★★★★★ (4.8) |
| **자율 루프(YOLO)** | 지원 (Composer) | 미지원 (대화형) | 지원 (CLI 연동) | 지원 (Plan-Execute) |
| **컨텍스트 대처** | 중간 (인덱싱 의존) | 낮음 | 중간 | 최상 (2M 대용량) |
| **최적 추천** | 고속 프로토타이핑 | 단순 타이핑 보조 | 복잡 알고리즘 구현 | 대규모 프로젝트 분석 |

- **의사결정 및 권장 아키텍처**: 
  - 정교한 알고리즘과 높은 정밀도를 요하는 작업에는 **OpenAI Codex(GPT-5.2)** 엔진을 최우선으로 권장합니다.
  - 하지만, 수백 개의 모듈이 얽혀 있는 대규모 엔터프라이즈 코드베이스를 리팩토링하거나 레거시 분석을 진행할 때는 200만 토큰의 문맥을 소화하는 **Google Antigravity(Gemini 3 Pro)**를 채택하는 것이 기술적 부채를 예방하는 가장 합리적인 선택입니다.

## 🎯 시니어 멘토의 오늘의 브리핑 (Micro-Lecture)

- **핵심 요약**: 도구의 성능이 아무리 뛰어나도, 개발자가 '목표 지점'을 명확히 명시하지 않으면 AI는 엉뚱한 산으로 갑니다. 도구들의 특징을 이해하고, 내 프로젝트의 크기와 성격에 따라 유연하게 도구를 교체해가며(Cross-Model & Cross-Tool Collaboration) 협업하는 능력을 길러야 합니다.
- **도전 과제**: 오늘 여러분이 사용하는 에디터(Cursor 또는 Antigravity)에서 제공된 칸반 실습을 진행하며, **"카드를 더블클릭하면 텍스트를 수정할 수 있는 인라인 편집 기능"**을 추가하라고 에이전트에게 요청해 보고, 에이전트가 기존 드래그 앤 드롭 이벤트와 충돌 없이 깨끗한 코드를 짜내는지 검증해 보세요.
