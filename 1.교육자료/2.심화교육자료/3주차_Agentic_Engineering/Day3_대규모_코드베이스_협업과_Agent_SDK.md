# 🚀 3주차 3일차: 대규모 코드베이스 제어와 SDK 기반 에이전트 자동화

안녕하세요! 시니어 멘토입니다.

어제 우리는 원격 클라우드 샌드박스를 개설하고 Sprites.dev를 통해 코드를 안전하게 빌드하여 GitHub PR을 상신하는 법을 배웠습니다. 오늘은 실무 아키텍처에서 가장 자주 직면하는 난제 중 하나인 **"수만 줄의 소스코드가 얽혀 있는 대규모 엔터프라이즈 코드베이스를 에이전트가 어떻게 길을 잃지 않고 조작하게 할 것인가?"**에 대한 모범 사례(Best Practices)를 다루겠습니다.

아울러 에이전트를 터미널 명령 입력창이 아닌, 내 코드에서 프로그래밍 방식으로 제어할 수 있게 해주는 **Claude Agent SDK**의 가동법과 메신저 연동 비서인 **OpenClaw** 시스템을 학습하겠습니다.

---

## ☕ 1분 비유: 대규모 코드 제어는 국립박물관에 특화된 로봇 안내원을 배치하는 것이다
박물관 전체를 다 외워야만 손님을 안내할 수 있는 것은 아닙니다.

```text
- 나쁜 사례 (박물관 전체 도면을 로봇 머리에 다 구겨 넣기)
  로봇 안내원에게 국립박물관에 소장된 모든 유물 사진과 안내 가이드(대규모 소스코드 전체)를 매번 부팅할 때마다 전부 다운로드받게 합니다. 로봇은 과부하(컨텍스트 한계 초과)로 멈추거나, 엉뚱한 전시실 안내 정보를 뒤섞어 답변합니다. (컨텍스트 혼란)

- 좋은 사례 (전시 섹션 분류 인덱싱과 도구 스펙 쥐여주기)
  로봇에게 박물관의 대략적인 카테고리 색인표(Semantic Search Index)와 특정 유물실의 위치만 알려줍니다. 손님이 "조선시대 백자를 보여줘"라고 하면, 로봇은 박물관 전체를 외울 필요 없이, 색인표를 보고 '제3전시실(특정 서브 디렉토리)'로 곧장 달려가 해당 도자기의 라벨만 읽고 안내합니다. (효율적 파일 탐색)
```

- **`.claudeignore`**: 에이전트 로봇이 절대 들어가지 말아야 할 기밀 문서실이나 먼지 쌓인 창고(빌드 아웃풋, 서드파티 라이브러리 폴더)를 원천 차단하는 출입 금지 스티커입니다.
- **Agent SDK (조종 리모컨)**: 사람이 터미널에 명령어를 치는 대신, 프로그램 코드로 에이전트에게 **"이슈가 발생하면 몇 번 라인의 코드를 읽어서 수정해라"** 하고 조종용 무선 전파를 쏘는 리모컨입니다.

## 🎯 Section 1: 대규모 코드베이스(Large Codebases)에서의 컨텍스트 제어 기술

대기업의 모놀리식(Monolithic) 레포지토리나 거대한 프레임워크 프로젝트에서는 아무리 컨텍스트 윈도우가 큰 LLM(Gemini 3 Pro 등)이라도 한 번에 모든 소스코드를 넘기면 비용과 추론 정확도 면에서 실패할 확률이 큽니다.

### ⚙️ 대규모 코드 탐색 3단계 필터링 아키텍처
1. **정적 격리 (`.claudeignore` 설정)**:
   - 프로젝트 루트에 `.claudeignore` 파일을 배치하여 `node_modules/`, `dist/`, `.git/`, 대형 CSV 데이터 파일, 이미지 파일 등이 에이전트의 스캔 검색 인덱스에 들어오지 못하게 물리적으로 격리합니다.
2. **의미론적 검색 (Semantic Search) 선행**:
   - 에이전트가 코드를 고치기 전에 파일 목록을 직접 다 읽게 하지 않고, `ripgrep`이나 의미론적 키워드 검색 도구를 통해 **수정이 필요한 후보 파일 3~5개만 골라내게** 프롬프트를 튜닝합니다.
3. **영역 타겟팅 지시**:
   - 에이전트에게 태스크를 부여할 때 "전체 프로젝트에서 버그를 찾아라"가 아닌 **"현재 `src/services/billing/` 폴더 안의 파일들만 컨텍스트에 담아 검사하라"**고 작업 경계(Working Boundary)를 칼같이 그어주어야 합니다.

---

## 🎯 Section 2: 엔터프라이즈 개발 팀 협업 베스트 프랙티스

여러 명의 개발자와 복수의 AI 에이전트가 공유 코드베이스에서 동시 작업할 때 생기는 충돌(Git Conflict) 방지 대책입니다.

- **원자적 기능 단위 브랜치 전략**: 1개의 브랜치에서는 반드시 하나의 지라(Jira) 티켓 기능만 구현하도록 강제하며, 수정 범위가 겹치지 않게 에이전트의 작업 대상 폴더를 격리합니다.
- **수동 최종 승인제 (Mandatory Human Peer Review)**: 에이전트가 GitHub PR을 자율적으로 생성할 수는 있지만, **마스터(main) 브랜치로의 최종 병합(Merge) 권한은 반드시 사람 개발자의 승인이 있도록 CI/CD 파이프라인에서 하드 브로킹**해야 합니다.

## 🎯 Section 3: Claude Agent SDK를 활용한 에이전트 프로그래밍 제어

터미널 입력창을 통하지 않고, Node.js나 Python 스크립트 코드로 에이전트에게 명령을 내려 자율 가동하는 방법입니다.

```typescript
// 예시: src/scripts/auto-refactor.ts
// Claude Agent SDK를 이용해 스키마 변경 시 관련 코드를 자동으로 리팩토링하는 스크립트
import { ClaudeAgentSDK } from '@anthropic-ai/agent-sdk';

const sdk = new ClaudeAgentSDK({
  apiKey: process.env.ANTHROPIC_API_KEY
});

async function main() {
  console.log("1. 데이터베이스 스키마 변경 감지됨...");
  
  // 에이전트 객체 생성 및 작업 지시서 주입
  const agent = await sdk.createAgent({
    projectPath: '/mnt/d/Programming/2026.AutoReport/3.autoreport_크롬확장앱',
    rulesFile: 'agents.md'
  });
  
  console.log("2. 에이전트 자율 리팩토링 기동...");
  const result = await agent.runTask(
    "models.py의 스키마 변경에 맞춰, schemas.py의 Pydantic 모델 속성들을 최신화하고 단위 테스트를 가동해줘."
  );
  
  console.log("3. 에이전트 실행 결과:", result.summary);
}

main();
```

- **활용처**: 데이터베이스 테이블 설계가 변경되었을 때 백엔드 API DTO 스키마 파일을 동적으로 자동 갱신해 주는 CI/CD 빌드 단계 자동화에 매우 강력합니다.

## 🎯 Section 4: 비개발 업무 자동화와 메신저 연동 OpenClaw

AI 코딩 에이전트 기술은 개발 이외의 영역에서도 놀라운 효율을 보여줍니다.

- **Claude Cowork (일상 업무 자동화)**:
  - 기획서(PDF), 예산 파일(Excel) 등이 담긴 폴더를 에이전트에게 지정하면, 에이전트가 가상 샌드박스에서 파이썬 판다스(Pandas) 라이브러리를 직접 작성·가동하여 복잡한 세무 보고서 요약본을 자동으로 만들고 이메일 초안까지 작성해 냅니다.
- **OpenClaw (메신저 연동 AI 사이드킥)**:
  - 텔레그램(Telegram)이나 와츠앱(WhatsApp) 메신저 API와 Claude Code 에이전트를 연결한 오픈소스 챗봇 아키텍처입니다.
  - 외부 출장 중에 스마트폰으로 텔레그램에 **"서버 로드율 확인하고, 문제 있으면 최신 릴리즈 핫픽스 PR 올려줘"**라고 메시지를 보내면, 메신저 봇이 샌드박스의 Claude Code를 SDK로 기동하여 무선 원격 제어 자동화를 달성합니다.

## 🏗️ 아키텍트의 의사결정 노트 (ADR - Architectural Decision Record)

### 결정사항: 지속적 유지보수 자동화 도구 - 스케줄 기반 크론탭(Crontab) vs SDK 기반 이벤트 트리거 에이전트
- **배경**: 배포된 서버의 린트 에러 및 서드파티 라이브러리 보안 업데이트 권고(Dependabot 알림 등)를 에이전트에게 맡겨 자율 패치하고자 합니다.
- **대안 비교**: 
  - *대안 A (시간제 크론탭)*: 매일 새벽 3시에 에이전트를 띄워 전체 코드 검사를 수행함. (설계가 쉽지만, 아무 변경이 없는 날에도 비싼 API 요금이 발생함).
  - *대안 B (GitHub Webhook 기반 Event-driven SDK 실행)*: Dependabot 보안 경고 이벤트가 발생하거나 PR 빌드가 실패했을 때만, 즉시 Webhook 신호를 받아 SDK로 필요한 대상 부분에만 에이전트를 조준 사격 기동함.
- **의사결정 이유**: 비용 효율성과 반응 속도의 원칙에 따라, **대안 B(이벤트 트리거 SDK 방식)**를 표준 자동 유지보수 아키텍처로 결정합니다. 필요할 때만 컨테이너 가상 머신을 띄우고 에이전트 API를 호출하는 구조가 기업의 API 크레딧 자원을 가장 영리하게 활용하는 비즈니스 설계입니다.
